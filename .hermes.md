# ACP Gateway — правила работы для Hermes

Решение владельца 2026-10-23. Действует для всей разработки в этом репозитории,
пока владелец явно не изменит. Цель — двигаться к результату для пользователя
и не тратить время и токены на проверки, которые не меняют решения.

**Текущая очередь:** [последний раздел roadmap](road-map.md#9-очередь-дальнейшей-разработки).
Решение 2026-10-29: сначала завершить и проверить P4.19; новое направление Paperclip/узлов — после него, см. [P4.20](docs/plans/p4.20-paperclip-direction.ru.md). Обсуждение и план не разрешают реализацию или развёртывание.
[Раздел 0 точки возврата P4.13](docs/plans/p4.13-resumption.ru.md#owner-directive-2026-10-23)
сохраняет правила объёма и проверки; исторический порядок задач в нём не заменяет
актуальную очередь.

**Состояние 2026-10-26:** stable 0.2.7 опубликован; диспетчер — официальный GHCR
0.2.7, коннекторы — 0.2.6. P4.18 и ACL-follow-up реализованы. Остаток приёмки и
эксплуатационных улучшений — в roadmap; P4.13.1 уже в stable, полная живая матрица
открыта. Неполный baseline остаётся долгом, не предварительным gate.
[Поставка и проверки](docs/releases/0.2.7-publication.md).

## Объём проверки — по риску

- **Production-код безопасности, IPC, ACK/ACL, хранения данных:** тест
  RED→GREEN, прогон затронутых модулей на Windows и WSL, **одно** независимое
  ревью. Не более одного цикла исправления по ревью; если снова blocker —
  остановиться и эскалировать владельцу, не начинать новый круг.
- **Прочий production-код:** тесты затронутых модулей, `ruff check`,
  `ruff format --check`. Без независимого ревью, если владелец не попросил.
- **Только `tests/` и `docs/`:** один точечный прогон, без ревью.
- Один прогон на шаг. Не повторять тот же набор «для контроля» после
  исполнителя или ревьюера; их числа достаточно.
- Не расследовать историческую причину падения, если механизм уже
  воспроизведён и исправлен.
- Isolation guard (`tests/strict_isolation_runner.py`,
  `tests/external_effect_guard.py`) заморожен: не расширять и не дорабатывать
  без прямого поручения. Обычные прогоны `pytest` его не требуют.

## Git вместо ручных снимков

- Разрешены локальные коммиты и `push` рабочей ветки (не `main`) после
  каждого завершённого шага. Merge в `main`, теги, релиз, deploy — только с
  отдельного разрешения.
- Не строить хеш-манифесты исходников до/после прогонов: `git status`,
  `git diff` и коммит дают то же самое.

## Журнал и доказательства

- Запись на шаг — 5–10 строк: что сделано, коммит, команда, итог
  (passed/failed/skipped), что осталось. Без внутренних id делегаций
  (`deleg_*`) и без кодов замечаний (S1, L1, R1) без расшифровки.
- Доказательство — команда и итоговая строка в журнале. Scratch
  (`AppData/Local/hermes/cache/scratch`) одноразовый, ссылки на него в
  документы не ставить.
- В начале сессии читать этот файл, раздел 0 точки возврата,
  `git status` и `git log -5`, затем только файлы для текущего шага. Весь
  журнал и разделы 1–16 точки возврата целиком не перечитывать.

## Проверка и выпуск

Отдельные стенды, тестовые боты и тестовые диспетчеры не поднимать: других
пользователей у личного диспетчера нет. Новые версии проверяются сразу на
личном диспетчере и ПК владельца, затем выходят полным релизом и раскатываются
на остальные ПК штатным обновлением. Коннектор основного Windows-ПК работает из
editable Git-клона `%USERPROFILE%\source\repos\acp-gateway` на обычном Python/`.venv`.
Обновление: `scripts/run-source.ps1 service --role connector disable`,
`git pull --ff-only`, pip metadata/dependencies при необходимости, затем enable.
Старые `scripts/install.ps1`/`update.ps1` обслуживают uv tool и для этого ПК
не применяются. Прежний uv-пакет сохранён для отката, его updater отключён.
Порядок захода — [план P4.13.1, раздел 6](docs/plans/p4.13-work-mode.ru.md).

Заход 2026-10-25: rc1 опубликован и развёрнут с явного разрешения владельца.
Модельные вызовы владелец исключил: выполнены только initialize/health без новых
диалогов и prompts. Для дальнейших модельных сценариев нужен явный бюджет.

## Что не меняется

Без разрешения владельца — одно сообщение на весь заход приёмки, не на каждый
шаг:
- не обновлять диспетчер и коннекторы;
- не публиковать rc и релизы;
- не делать платных модельных вызовов.

Всегда: не трогать установки Hermes и чужие задачи Task Scheduler, не входить в
аккаунты и не менять логины, не просить пароли и токены.
ACL/ownership-политику не ослаблять. Права агентов расширять только через
рабочий режим по [плану P4.13.1](docs/plans/p4.13-work-mode.ru.md): он
утверждён владельцем, повторно обосновывать его не нужно. Безопасный режим
остаётся значением по умолчанию.
