Локально выполнено **только** `codex --version` и
`codex app-server generate-json-schema --out /tmp/acpgw-p419-codex-schema`.
Версия **codex-cli 0.164.0**. Не запускались initialize/thread/model turn,
не читались credentials или пользовательские диалоги, нет inference-запросов.
CLI предупредил о read-only PATH aliases, но обе команды завершились с code 0.
Сгенерированные schema — временные, не требуют сохранения огромного bundle
в репозитории. Обычного `python` в PATH нет; анализ JSON выполнен `.venv/bin/python`.

Из точных schema этой версии:

| Ответ / запрос | Нужные поля |
|---|---|
| `ThreadStartResponse` | `model: string`, `modelProvider: string`, `reasoningEffort: enum or null`, `thread` |
| `ThreadResumeResponse` | Те же поля |
| `ThreadReadResponse` | Только `thread`; нельзя предполагать те же top-level model/effort |
| `ModelListResponse` | `data`, `nextCursor` |
| `Model` | `id`, `model`, `defaultReasoningEffort`, `supportedReasoningEfforts`, `isDefault`; provider отсутствует |
| `TurnStartParams` | `model` и `effort` могут переопределять текущий и последующие ходы |

Default из каталога — рекомендация, не доказательство effective effort конкретного
диалога. `reasoningEffort: null` не заменять на medium. Provider не выводить по
префиксу model ID. Старые native peers могут не иметь полей; неизвестные данные
не должны ломать диалог. Каталог не доказывает entitlement конкретного аккаунта.

## Текущее место потери данных

`adapters/codex.py`, `_request`, обработка session/new и session/load:
native thread/start/resume response используется для `response.thread.id`,
после чего adapter возвращает только sessionId либо пустой объект. Top-level
model/provider/effort сейчас не проецируются. `_prompt` не переопределяет model/
effort в turn/start, но это не оправдывает выдачу локального config за observation.

`agents/model_control.py` имеет узкий options/set/recover контракт только
provider/model. `storage/models.py` хранит durable intent/observation для него.
Для effort потребуется отдельная явная проекция; нельзя молча подставить effort
в provider/model или обойти существующую unknown/confirmation семантику setter.
`telegram_context.py` уже умеет показывать последнее наблюдение provider/model,
но проекция managed adapters до неё не доходит.

Claude Code: `adapters/claude_code.py` передаёт settings.model в CLI, initialize
control response проверяет только success/object и отбрасывает response content.
Наличие и семантика effective model/effort ещё **не исследованы**. Не объявлять
CLI argument подтверждённой наблюдаемой моделью; provider может зависеть от
настроек Anthropic/Bedrock/Vertex, его нельзя выдумывать по названию модели.

## Следующая реализация

1. Сначала read-only observation Codex из start/resume: строгая bounded проекция
   идентификаторов + nullable effort, session/native binding и явный источник
   наблюдения. Поля отсутствуют/невалидны — unknown; сырые native объекты не хранить.
2. Провести observation через ACP/session/core/storage без изменения model setter
   semantics и без неявного подключения/turn при открытии панели. Проверить fake
   native peer с полными, отсутствующими и некорректными метаданными; два диалога
   не должны подменять observation друг друга, resume — обновлять только свой.
3. Сохранять и показывать effort в текущем контексте и job source snapshot;
   старые данные/ответы сохраняют честное unknown. Нужна проверка immutable footer
   после смены модели и границ доставки.
4. Отдельно исследовать read-only Claude Code contract. Только затем решать
   поддерживаемый selector/setter: каталог одного provider не превращать в
   произвольный provider switch, не делать inference ради проверки названия.

Codex runtime-проекция реализована следующим этапом, см. ниже. Claude остаётся
открытым; выбор/смена модели и effort для native adapters здесь не реализованы.

## Codex — реализация read-only наблюдения

`agents/observations.py` проецирует ограниченные идентификаторы и nullable effort;
секретные/невалидные поля превращаются в unknown. Codex adapter прикладывает
`_meta.acp-gateway.modelObservation` к existing session/new/load responses,
повторный attach уже загруженного thread возвращает прежнее наблюдение без RPC.
AgentClient хранит per-native-session cache, новый attach без метаданных очищает
старые значения. Core сохраняет evidence в channel_state namespace
`native_model_observation`, с идентичностью agent/native SID/created_at SQLite
диалога. Это отдельный read-only namespace, не model setter acknowledgment.

Internal ModelObserved после attach и до model prompt дополняет JSON job_context
один раз; последующие/finished изменения отклоняются. При ошибке записи prompt
не отправляется. Context/destination/result footer показывают effort только когда
он пришёл от native runtime. `/model state` читает native evidence отдельно от
состояния setter. Нет дополнительных model/list/thread/read/turn RPC ради панели.

Проверки: **387 passed** Telegram/core/API/storage; **114 passed** Codex direct/
real connector WS relay/native projection/secrets. Ruff check/format **321 файла**
и diff check чистые. Два диалога изолированы, dispatcher restart сохраняет данные
без reconnect, resume меняет только свой контекст, старые ответы неизменны.
Schema остаётся 12. Live inference/deploy здесь не выполнялись.

## Claude — источник и реализованная проекция

[Официальный headless contract](https://code.claude.com/docs/en/headless#read-session-metadata)
описывает model в `system/init`. Это stream-событие, не control initialize success
и не список supported models. `_read` теперь обрабатывает system/init;
model проецируется без выдумывания названия через runtime observation.
Provider/effort данная проверка документации не установила — пока unknown.
Не читать секретные env/config ради подписи и не выдавать CLI model за observation.

Нужно учесть фазу: если init приходит после user input, source footer должен
называть это наблюдением при запуске хода, а не до запроса. Проекция привязывается
к исходному session_id, исключает parent_tool_use_id и late/foreign frames;
не должна затирать source snapshot другого хода или старого ответа.

Реализовано: только первый init данного owned child с точным session_id и без
parent_tool_use_id. Host child хранит ограниченную проекцию, turn получает её
снимок до записи user input; init во время turn может дополнить снимок только
до done. Native prompt response переносит этот snapshot через ACP `_meta`;
AgentClient выдаёт internal ModelObserved перед TurnFinished/TurnFailed.
Core записывает одну проекцию в job_context и сохраняет per-dialogue observation
отдельно от setter state. Metadata не превращает ошибочный turn в успешный.
Provider/effort для `claude.system.init` принудительно unknown — их наличие в
неподтверждённых полях не считается контрактом. Старая wire shape без metadata
сохранена. Init после done остаётся только last-known child evidence для будущего
хода, не приписывается завершённой задаче; дубли вообще не заменяют first init.

Footer использует явное «наблюдение native init», а не «перед запросом».
Новый prompt/query ради model metadata не отправляется. При post-turn disk error
job становится failed, но уже выполненный native turn не replayed; следующий
запрос владельца продолжает тот же диалог.

Проверки: **437 passed** общая Telegram/core/API/privacy регрессия;
**145 passed** native Claude/Codex/connector WS/projection/privacy. Есть отдельные
сценарии двух диалогов, foreign/подагент init, duplicate/late first init,
невалидный model, зарегистрированный секрет, native error и post-turn storage
failure. Ruff **322 файла**, diff check чистые. Live inference не вызывался.

## Ревью отображения Claude/Hermes/Goose, 2026-10-27

Найдено и исправлено:

- **Goose/generic ACP.** Goose 1.53 (записанные fixtures) в session/new и
  session/load присылает стандартные `configOptions`: `model` (category model),
  `thinking_effort` (category thought_level) и select `provider` без категории.
  Шлюз их отбрасывал, и панель всегда писала «модель неизвестна».
  `observations.config_observation` проецирует только select-значения через тот же
  ограниченный identifier/redaction; источник `acp.config_options`. Значение
  обновляется по `config_option_update` (текущее состояние, не история) и
  закрепляется в job_context перед запросом. Если агент модель не сообщил,
  снимок задачи не перезаписывается, а для generic остаётся прежний fallback
  на model.options/model_state. Новых RPC ради панели нет.
- **Claude.** Модель приходит только в `system/init` после ввода, поэтому
  повторный attach без метаданных больше не стирает последнее наблюдение
  (раньше после переподключения панель показывала «модель неизвестна» до ответа).
  Ход без собственного init по-прежнему честно даёт unknown в снимке задачи.
- **Подпись.** Единый формат `Агент · [провайдер ·] модель [· effort]`:
  неизвестный провайдер опускается, а не пишется «провайдер неизвестен».
  Goose называется «Goose», а не сырым `goose`; generic — именем профиля.
  Подсказки при отсутствии модели: Hermes — «ещё не запрашивалась · /model»,
  Claude — «станет известна после первого ответа».
- **Режим выполнения.** Для не-Hermes агентов вместо «Как Hermes» —
  «С подтверждениями».
- Тест `test_connector_multinode` сравнивал ответ целиком без подписи источника
  (пропущен при переходе на v3 footer); переведён на `answer_body`.

Проверки: полный pytest **2499 passed / 236 skipped** (350 с); Ruff check/format
322 файла и diff check чистые. Живой Goose/Claude/Hermes не запускался; Goose
проверен по записанному трафику 1.53.0.
