## 1. Цель

Владелец хочет вести полноценную удалённую разработку на ПК с коннектором:
выбрать в Telegram компьютер и любого агента (Hermes, Codex, Claude Code), дать
задачу и получить результат. Без десятков нажатий «разрешить», без обрыва на
середине и без потери чата при перезапуске.

До реализации P4.13.1 managed Codex и Claude Code имели следующие ограничения:

- Claude спрашивает про каждое действие, включая чтение файлов
  (`claude_code.py`, `TOOLS` + `permissions.ask`);
- у Claude лимит 16 шагов (`config.py`, `max_turns`);
- `--safe-mode` отключает `CLAUDE.md`, skills, plugins, hooks и MCP;
- `--no-session-persistence` — чат не сохраняется;
- Codex по умолчанию только читает, сеть выключена, `approvalPolicy:
  untrusted`;
- у обоих нет отмены хода и восстановления после потери процесса.

Живую приёмку проводить в таком виде бессмысленно: этим режимом никто не
будет пользоваться.

Реализация 2026-10-25 снимает эти ограничения в рамках описанного ниже плана.
Для resume хранится локальная привязка ID к профилю/mode/cwd/среде, с exclusive
OS lease и durable attached/busy состояниями. После crash/unknown cleanup
продолжение блокируется; автоматического снятия такого fence в этом подэтапе нет.
Подтверждённый clean restart восстанавливает исходный чат без повтора prompt.

## 2. Решение владельца 2026-10-23

1. **Два режима для каждого managed-агента: «Безопасный» и «Рабочий».**
2. **В рабочем режиме у агента включён его собственный auto mode** — агент сам
   решает, что безопасно, а не спрашивает человека про каждое действие.
3. Безопасный режим остаётся, как сейчас, — для чужих или важных проектов.

## 3. Как устроено — минимум новой работы

**Режим — свойство профиля агента на коннекторе, а не новая команда в
Telegram.** Setup создаёт профиль с режимом; чтобы были доступны оба режима,
создаются два профиля, например `claude` и `claude-work`. В Telegram они
появляются в уже существующем выборе агента. Новой команды, хранения
состояния и UI не нужно.

Переключение режима внутри диалога отклонено. Режим разрешений задаётся при
запуске native-процесса, его смена означала бы перезапуск процесса и новый
путь повышения прав из Telegram. Вернуться к этому можно позже, если двух
профилей окажется мало.

**Что уже есть и переиспользуется, не переделывать:**

- `/mode` в Telegram: «Как агент» / «Без подтверждений» (`core/gateway.py`,
  `execution_mode`; `core/approvals.py`). Работает поверх любого профиля: в
  рабочем режиме агент спрашивает редко, а `/mode` → «Без подтверждений»
  одобряет и эти редкие вопросы. Отдельный «режим без вопросов» не делать.
- Отмена хода: ядро вызывает ACP `session/cancel`
  (`core/gateway.py`, `agent(...).cancel`), кнопка «стоп» в Telegram уже есть.
  Адаптерам нужно только поддержать `session/cancel`.
- Восстановление: `agents/client.py` вызывает ACP `session/load`, если агент
  объявил `loadSession`; восстановление диалогов в Telegram уже работает для
  Hermes. Адаптерам нужно поддержать `session/load` и объявить capability.
  Это отдельный проверяемый подэтап: сохранить native ID и привязку к
  среде/профилю/cwd, восстановить исходный чат после перезапуска и не
  повторять запрос с неизвестным исходом. Наличие метода в ядре само по
  себе не доказывает восстановление.
- Hermes и Goose: режимы уже есть (политика Hermes / «Как Hermes»,
  `session_mode` у Goose). Новой работы для них нет. Только показывать режим в
  карточке агента теми же словами, если это дёшево.

## 4. Что делает рабочий режим

### Claude Code (CLI 2.1.309 установлен, флаги проверены по `--help`)

| Сейчас (безопасный) | Рабочий |
|---|---|
| `--permission-mode manual` + `ask` для всех 6 инструментов | `--permission-mode auto` (классификатор Claude). Оставшиеся вопросы идут через `--permission-prompt-tool stdio` в Telegram, как сейчас. |
| `--tools Read,Glob,Grep,Edit,Write,Bash` | `--tools default`: в том числе WebFetch, WebSearch, субагенты и todo |
| `--safe-mode`, `--setting-sources ""`, пустой MCP, `--disable-slash-commands`, `disableAllHooks` | `--setting-sources user,project,local`, без `--safe-mode`. Подхватываются `CLAUDE.md`, skills, plugins, hooks и MCP пользователя. |
| `--no-session-persistence` | Чат сохраняется; его можно продолжить в терминале через `claude --resume <id>`. |
| `max_turns: 16`, `turn_timeout: 600` | `max_turns: 100`, `turn_timeout: 3600` по умолчанию для рабочего профиля. |

Владелец подтвердил 2026-10-23: auto mode доступен на любой подписке.
Запасной вариант не нужен, доступность отдельно не исследовать.

### Codex (CLI 0.163.0, поля проверены по схеме `app-server generate-json-schema`)

| Сейчас (безопасный) | Рабочий |
|---|---|
| `sandbox: read-only`, `approvalPolicy: untrusted` | Preset Auto: `workspaceWrite` + `approvalPolicy: on-request` |
| вопросы идут человеку | `approvalsReviewer: auto_review` — аналог auto mode: субагент Codex сам одобряет или отклоняет выход за sandbox |
| `networkAccess: false` | `networkAccess: true` — нужно для `git push`, `uv sync`, `npm install` |
| треды | `ephemeral: false`, явно — нужно для восстановления |

`approvalsReviewer` и `ephemeral` есть в `ThreadStartParams` и
`ThreadResumeParams` версии 0.163.0.

### Общее для обоих режимов

Не относится к безопасности, поэтому делается сразу в обоих режимах:

- **Отмена хода.** ACP `session/cancel`: Codex — `turn/interrupt`, Claude —
  control request `interrupt` протокола stream-json. Сообщать честно:
  «остановлено, уже выполненные действия не откатываются».
- **Восстановление.** ACP `session/load` + capability `loadSession`: Codex —
  `thread/resume` по сохранённому `threadId`, Claude — новый процесс с
  `--resume <session-id>`. В безопасном режиме для этого нужна persistence:
  включить её и там, так как она не расширяет права. Правило «не отправлять
  повторно запрос с неизвестным исходом» остаётся.

### Как проводится — решение владельца 2026-10-23

Других пользователей у личного диспетчера нет, поэтому отдельные стенды и
тестовые боты не нужны. Проверка идёт сразу на целевой схеме: личный
диспетчер и ПК владельца, затем полный релиз.

Новые типы агентов (`kind: codex`, `kind: claude_code`) должен понимать и
диспетчер. На 0.2.2 это требовало обновления диспетчера первым; переход уже
выполнен. Текущее развёртывание — 0.2.7/0.2.6; шаги 1–2 ниже сохраняют
исторический порядок первого захода, не поручение повторно обновлять установки.

1. **Windows-коннектор этого ПК — установка из checkout вместо uv-релиза.**
   Уточнение владельца 2026-10-25: editable Git-клон и обычный Python venv,
   запуск без uv tool; старые checkout scripts всё ещё используют uv tool.
   [Новая инструкция](../setup/windows-source.md).
   Сохраняются прежние пути
   ([distribution](../setup/distribution.md#checkout-scripts-linuxwsl-and-windows),
   [service](../setup/service.md)):
   - отдельный клон на диске Windows, ветка `feature/p4.13-codex-managed`;
   - обычный Python 3.12+ создаёт `.venv`, пакет устанавливается `pip install -e .`;
   - старую задачу остановить/удалить старым CLI, новую установить через
     `scripts/run-source.ps1 ... service --role connector install` и enable;
   - старый registry updater отключить, config/env/data/ключ сохранить.

   Текущие config/env/data сохраняются, привязка к диспетчеру остаётся.
   Обновление — остановить задачу, `git pull --ff-only`, обновить metadata/dependencies
   через pip при необходимости и запустить через `scripts/run-source.ps1`.
   Обновления из Telegram/PyPI к этому ПК не применяются: скрипты checkout не
   переключаются на PyPI. Остальные ПК обновляются релизами.
2. **Личный диспетчер — prerelease (rc) из ветки** штатным обновлением со
   snapshot и откатом из P4.15. Путь rc уже проверен на 0.2.0rc1–rc8. Заодно это
   приёмка P4.15.1.
3. **Сценарии выше**, плюс остаточная приёмка P4.17 (подключение ПК), если
   понадобится перепривязка.
4. **Полный релиз** и раскатка на остальные ПК штатным обновлением из CLI или
   Telegram.

Перед шагом 1 Hermes одним сообщением спрашивает владельца: модельный бюджет и
подтверждение «выпускаю rc и обновляю диспетчер и этот коннектор». Ответ на
это сообщение — разрешение на весь заход, а не на каждый шаг.

## 7. Стыковка со следующими пунктами

### 7.1 Переиспользовать восстановление для будущего списка чатов

- **`session/load` — это «открыть чат по native ID».** ID приходит из
  сохранённой привязки диалога, а позже — из списка. Хранить вместе с ним
  `cwd` чата (Claude ищет сессию по каталогу проекта) и профиль. Тогда пункт
  «список native-чатов» переиспользует этот путь; discovery (Codex
  `thread/list`, Claude — файлы сессий профиля), проверка scope и выбор
  остаются отдельной работой, а не автоматически готовой возможностью.
- **Рабочий профиль использует настоящий профиль агента**, без отдельного
  `agent_home` / `CODEX_HOME` / `CLAUDE_CONFIG_DIR`. Иначе чаты из Telegram не
  видны в терминале, а список чатов пуст. Отдельный home — только для тестов.
- **Режим при подключении к существующему чату — режим выбранного профиля**,
  показанный явно. Это согласуется с решением 10.5 точки возврата («изменение
  только явно»): выбор профиля и есть явное действие. Фраза 10.5 «не поручение
  ослаблять safe defaults» уточнена решением 2026-10-23: рабочий режим —
  явный выбор владельца. Для будущего выбора произвольного native-чата
  действие должно явно называться «Продолжить в рабочем режиме», а не
  просто «Открыть»: изменение разрешений нельзя прятать за выбором чата.

### 7.2 Не входит

- Сам список native-чатов и выбор из него — следующий пункт P4.13.
- Подключение к чату, **открытому сейчас** в терминале или Desktop (решение 10.1
  о равноправных источниках). Это другой механизм: вендорские Claude Remote
  Control / Channels и мультиклиентный Codex app-server. Отдельное
  исследование, см. очередь.
- Дописывание во время хода (Codex `turn/steer`) — позже.
- Одновременная запись в один живой чат из терминала или Desktop и из Telegram
  невозможна без официальных механизмов вендора. Не делать.
- `bypassPermissions`, `danger-full-access`, `--yolo` — не использовать.

## 8. Принятые риски

- Рабочий режим — агент с правами пользователя, которым управляют из Telegram.
  Компрометация Telegram-аккаунта владельца даёт выполнение команд на ПК.
  Защита — существующий allowlist Telegram и явный выбор рабочего профиля в
  setup. Владелец принимает этот риск ради удобства.
- Auto mode и `auto_review` — оценка моделью, а не sandbox. Вендоры прямо
  говорят, что риск снижен, но не устранён.
- Hooks и MCP пользователя в рабочем режиме Claude срабатывают по командам из
  Telegram.
