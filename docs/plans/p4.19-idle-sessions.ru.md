# P4.19.7 — инвентаризация и очистка простаивающих runtime

## Состояние перед реализацией, 2026-10-27

> **Обновление после 4.19.2 (тот же день):** Codex при подтверждённой остановке
> app-server теперь вызывает `sessions.close(confirmed=True, interrupted=True)`, как
> Claude: простаивающие потоки освобождаются, ход с неизвестным исходом становится
> `interrupted`. Появился `FencedBinding` и владельческий release (`releaseFence`,
> `ManagedSessions.release/fenced`), ключ привязки больше не включает executable и
> WSL PATH/python. Пункты ниже про «busy без interrupted пути» относятся к Claude-
> only состоянию до этого изменения; закрытие по простою должно использовать
> подтверждённую остановку, иначе само создаст fence.

Аудит исходников начат после native model observation в 4.19.2. Реализации
этого подпункта ещё нет. Native Windows/WSL/frozen проверки shell из 4.19.2
сохраняются как отдельный открытый долг, а не считаются выполненными.

Подтверждено точными исходниками:

- `CodexProcessManager._streams`: один native app-server на ACP transport;
  внутри `CodexAcpTransport._sessions` несколько native thread ID. Счётчик
  `running_sessions` считает `_turns`, не число live процессов/диалогов.
- `ClaudeCodeProcessManager._streams`: один transport содержит `_children`
  (child на диалог и возможный warm child). Менеджер уже учитывает aggregate
  max_sessions/spawning/opening; `running_sessions` также считает только ходы.
- `connectors/commands.py` держит managers между control reconnect и закрывает
  их при остановке коннектора. Ни manager, ни settings Codex/Claude не имеют
  таймера idle cleanup. `maintenance_status()` возвращает строго существующие
  пять полей admission; нельзя молча добавить туда произвольные inventory поля.
- `ConnectorMaintenance.session_control` относится только к Hermes и локальному
  maintenance-интерфейсу. Это не готовый remote inventory API для Codex/Claude.
- `ManagedSessions.close(confirmed=True)` освобождает leases и переводит
  attached/empty-attached в idle/empty-idle; busy без отдельного явного interrupted
  пути не очищается. Неподтверждённый stop сохраняет fence. Текущий метод закрывает
  все leases данного stream, поэтому не подходит для независимого удаления одного
  Claude child без дополнительного узкого release-контракта.
- `AgentClient._watch` при EOF очищает `_attached`; idle cold resume может затем
  пройти существующим load, если provenance освобождён после подтверждённого stop.
  Переотправка prompt после потери связи автоматически не делается.

Это объясняет живой WSL launcher при `running_sessions: 0`, но не доказывает
причину каждого исторического зависания. PID Windows launcher не равен числу
Linux процессов или всех фоновых инструментов.

## Реализация по шагам

1. Отдельная bounded inventory-проекция owned runtime/диалогов: kind/environment,
   непрозрачный handle, active/pending/approval/closing/uncertain, monotonic age.
   Показывать отдельно активные ходы, загруженные диалоги и наблюдаемые owned
   launchers. Не заявлять эти числа полной системной process inventory.
   Не возвращать stdout/stderr, prompts, credentials, полный argv/environment.
2. Учёт последнего реального действия и локальная idle policy; плановое значение
   по умолчанию 30 минут, configurable с возможностью выключить. Уточнить
   schema/config bounds и совместимость wizard/profile manifests при реализации.
   Опрос inventory не продлевает срок жизни, время — monotonic. Busy, request,
   opening, approval, unknown cleanup и maintenance reservation — отдельные fences.
3. Codex очищать только целый idle transport: нельзя закрыть shared app-server
   ради одного диалога, пока другой работает. Сохранить native IDs и leases до
   подтверждённого cleanup, последующий load — без replay пользовательского текста.
4. Claude: выбрать явную гранулярность. Целый transport можно закрывать только
   когда все его дети/запросы/подтверждения idle. Для независимого child cleanup
   сначала нужен per-session lease release и lazy restore без разрыва чужого хода;
   нельзя просто удалить child из `_sessions`, иначе следующий prompt закроет
   общий transport с работающими соседями. До готовности такого контракта показывать
   ограничение честно, не имитировать per-dialogue cleanup.
5. Inventory RPC — согласованная capability и отдельные строгие quotas/bounds,
   старые peers дают «не поддерживается». Telegram — кнопка ПК и страницы, read-only
   status не подключает модель. Чужие чат/названия не раскрываются: native IDs
   сопоставляются с owned dispatcher rows, остальные runtime показываются агрегатно.
6. Проверки: реальный fake-native subprocess → idle stop → same-ID resume/history,
   две параллельные сессии (busy сосед не закрывается), queued-request race,
   approval/model operation, maintenance, unverified WSL stop, stale handles,
   unknown outcome/no prompt replay, ownership/pagination в боте, legacy peers.

## Точка продолжения

**Решение владельца по ревью, 2026-10-28:** для Claude текущая очистка остаётся
на уровне всего транспорта; отдельное вытеснение простаивающих child при
заполнении лимита и безопасное восстановление через per-session lease вынесены
в следующий этап. При постоянной активности одного диалога остальные child
этого транспорта могут оставаться запущенными и занимать `max_sessions`. Это
ограничение показывается в Telegram и не считается решённым по общему таймеру.

2026-10-28: начата локальная inventory транспорта Codex/Claude: непрозрачный
handle, число загруженных диалогов, наблюдаемых живых launcher, ходов, запросов
и approvals, closing/uncertain, environment и ограничение 32 строк. Время
последней принятой операции и её завершения учитывается monotonic; чтение
inventory таймер не меняет. Пять maintenance counters сохранены.

Добавлен connector-only idle cleanup целого транспорта с настройкой
`idle_timeout` (по умолчанию 1800 с, 0 отключает, максимум 86400). Проверяются
работающие ходы, запросы, approvals, очереди, opening, maintenance и uncertainty;
закрытие заявляется синхронно до yield. Пока cleanup не закончен, открытие нового
транспорта ждёт освобождения bindings, а maintenance видит opening. При ошибке
остановки остаётся uncertainty. Fake-native интеграции проверяют остановку и
возобновление того же диалога Codex и истории Claude без повтора prompt.
Добавлены согласуемая capability и read-only bounded RPC с отдельной квотой,
проверкой эпохи и доступа к ПК. Сводка содержит агрегаты по объявленным профилям,
не текст или названия чужих диалогов; страницы по 8 профилей. Для текущего чата
диспетчер запрашивает совпадения до 32 принадлежащих ему ID из 50 последних;
коннектор возвращает только номера совпадений, имена берутся из локальных записей.
Карточка ПК в Telegram показывает процессы, диалоги, ходы, запросы, approvals,
состояние cleanup и uncertainty. Старый peer сообщает, что возможность не
поддерживается. Тесты проверяют handshake двух версий, pagination, отсутствие
model start, privacy, shared busy Codex, same-ID resume и историю Claude,
локальные fences и неподтверждённый cleanup. Нет live Windows/WSL evidence;
автоматическое завершение не объявляется проверенным на реальных хостах.
Публикация, раскатка и произвольный system-wide kill не входят в этап.
