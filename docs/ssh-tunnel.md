# SSH-туннель Paperclip: только предварительный просмотр

**Реализация не готова к эксплуатации.** `scripts/ssh_tunnel.py` не установлен
в `acpgw`. Команды `prepare`, `start`, `stop` отключены без вызова systemd и
записи файлов: принадлежность уже работающего процесса unit нельзя надёжно
установить по marker, хешам и FragmentPath. Это также исключает небезопасное
создание в подменённых каталогах и частичное создание. Остановка ранее созданных
unit этой утилитой недоступна даже при повреждённом marker; обследуйте их отдельно,
не останавливая чужие службы.

Команда `preview` печатает образец SSH-конфига и команду, ничего не записывает,
не запускает SSH и не проверяет файлы, серверы или ключи:

```sh
python scripts/ssh_tunnel.py preview demo \
  --host gateway.example --user alice --port 22 \
  --jump jump.example --jump-user alice --jump-port 22 \
  --key /home/user/.ssh/tunnel_key --known-hosts /home/user/.ssh/tunnel_known_hosts \
  --config /home/user/tunnel/ssh_config --local-port 22 --remote-port 8123
```

Предусмотрен **обратный** `-R`: порт 8123 на шлюзе `0.0.0.0` направлен на
`127.0.0.1:22` машины, запускающей SSH. Этот bind может открыть локальный SSH
внешней сети; нужен отдельный контроль firewall, политики доступа и настройки
`GatewayPorts`/`AllowTcpForwarding`/`PermitListen` на шлюзе. Сервер может
ограничить или отклонить bind; успешный preview ничего этого не подтверждает.

Оба host key (с учётом нестандартных портов) следует проверить по независимому
доверенному каналу и внести в отдельный защищённый `known_hosts`. Сам preview не
оценивает его содержимое, владельца или права, равно как и защиту ключа, каталогов
и конфигурации; `StrictHostKeyChecking` не доказывает доверие к самому файлу.
Нужны безопасная реализация хранения, lifecycle и диагностики и отдельная проверка
перед использованием. Сеть, доступ к шлюзу и работающий unit не проверялись.
