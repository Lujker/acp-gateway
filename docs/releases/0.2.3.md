# ACP Gateway 0.2.3

This release adds experimental managed Codex and Claude Code connectors and
agent profile management from Telegram. It builds on 0.2.2 pairing and updates.

- **Managed Codex and Claude Code (experimental).** A connector can start a
  dedicated local `codex app-server` or `claude` process, natively or on Windows
  through WSL. Each agent has explicit **safe** (default) and **work** profiles.
  Work enables native automatic review and the agent's normal tools/settings.
- Native turn cancellation and scoped resume of gateway-owned persisted chats,
  with durable unknown-outcome fences and exclusive gateway session ownership.
- **Telegram profile management** (opt-in `connector.remote_profiles`): open
  `/profiles <computer>` or **Computers → computer → Configure profiles** to add,
  remove or change agent profiles and working directories on a connector.
- **Clearer Telegram output:** Codex work updates are shown separately from the
  final answer; result cards and multipart delivery are improved.
- Windows connector fixes: WSL helper consoles are hidden, the activity watcher
  no longer shows a permanent "working in background" cursor, and a failed ACL
  check no longer stops the activity watcher silently.
- Profile requests tolerate clock skew between dispatcher and connector.
- [Editable Windows connector](../setup/windows-source.md) that runs in a normal
  Python venv, independently of uv tool installations.

## Upgrade notes

Upgrade the dispatcher first, then connectors one at a time; see the
[Russian upgrade instructions](../setup/update-0.2.3.ru.md).

- The dispatcher database migrates **schema 9 → 10** on first start. Rolling back
  to 0.2.2 requires the pre-upgrade database snapshot, not only the old image.
- Existing configuration, keys, computer IDs and Hermes/Goose profiles stay as
  they are. Managed Codex/Claude profiles are added only when configured.
- A 0.2.2 connector keeps working with a 0.2.3 dispatcher. To use managed
  Codex/Claude on a computer, upgrade its connector to 0.2.3.

## Known limitations

Managed Codex/Claude remain experimental. Owner acceptance confirmed Codex and
Claude use through Windows→WSL and profile editing from Telegram. Telegram
approvals, native cancel/resume and reboot/logon persistence have automated
coverage but no recorded live acceptance; a live macOS connector check is open. Desktop/CLI chat import
and attaching to an existing Codex or Claude Desktop session are not included.
The full native Windows test suite still has known baseline failures; release
CI runs the full suite on Ubuntu and native smoke checks on Windows, macOS and
Linux ARM.

Artifacts: wheel, sdist, deployment bundle, locked requirements and SHA256SUMS.
Docker image: `ghcr.io/lujker/acp-gateway:0.2.3` (Linux x86_64).
