# ACP Gateway 0.2.1

This release adds Telegram update management for the dispatcher and connectors,
with exact-version confirmation, durable operation history and restart-aware
notifications. Remote execution is disabled by default and requires a separate,
locally configured updater companion.

- Independent Linux user-service and Windows logon-task lifecycle for the companion.
- Managed uv service updates and Linux Docker-host image replacement with database
  backup, health checks and recovery on acknowledged failure.
- Local diagnosis and audited resolution of retained unknown executor operations.
- Registration of reviewed immutable local Docker images without automatic pull/build.
- Connector activity watcher retries after transient status publication failures.
- Saved env-file selection and explicit service reinstallation guidance after
  connection changes.
- Telegram context, recent conversations, favorites and recovery controls developed
  after 0.2.0.

Upgrade the dispatcher first, then connectors one at a time. Configuration,
enrollment keys and data remain in their existing locations. Windows managed update
returns after queuing; wait for `acpgw update --status` to report success.

[Russian upgrade instructions](https://github.com/Lujker/acp-gateway/blob/v0.2.1/docs/setup/update-0.2.1.ru.md)
· [Remote updater setup](https://github.com/Lujker/acp-gateway/blob/v0.2.1/docs/setup/remote-updates.md)

Scope: one owner, one target at a time, newer stable major.minor.patch releases,
registry uv installations on Linux/Windows and a Linux Docker dispatcher. macOS,
batch updates, prerelease targets and Git/file installation updates are excluded
from the Telegram updater. Native service update acceptance is not claimed by
cross-platform package/binary CI. Existing live acceptance remains provisionally
closed and reopens on reported problems.

Artifacts: wheel, sdist, deployment bundle, locked requirements and SHA256SUMS.
Docker image: `ghcr.io/lujker/acp-gateway:0.2.1` (Linux x86_64).
