# ACP Gateway 0.2.8

## Fixed

- **Dialogues survive a dropped computer connection.** A short loss of the link
  between a computer and the dispatcher no longer ends a running Codex or Claude
  Code turn. The connector keeps the agent working for up to 5 minutes; after it
  reconnects, messages in both directions are delivered without loss or
  duplicates. Revocation and a deliberate stop still close streams at once.
- **Claude API errors keep the dialogue.** When Claude reports an error for a turn
  (overload, rate or budget limit, authentication), only that task fails, with a
  short notice; the same dialogue accepts the next message. Native diagnostics
  stay private.
- **Interrupted Claude Code dialogues can be resumed.** After a turn timeout, a
  lost connection or an unconfirmed stop, the dialogue used to be blocked for
  good. Once the connector confirms the Claude process stopped, Telegram shows
  that the turn was interrupted and offers **▶ Возобновить диалог**. The native
  chat reopens with its history; the interrupted request is never resent.
  Codex dialogues keep the previous strict behaviour.
- Managed Codex turns no longer end on very large native output lines.

## Upgrade

Update **both** the dispatcher and the connectors. Stream resume and the resume
button need new versions on both sides; with an older peer the previous
behaviour remains (an older dispatcher shows a Claude API error as an empty
answer, but the dialogue is kept).
