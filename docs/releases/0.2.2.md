# ACP Gateway 0.2.2

This release adds connector-first pairing and turns dispatcher/connector updates
into a normal out-of-box capability.

- New computers pair from `acpgw connect`: the owner confirms the exact request in
  CLI or Telegram, and the connector receives its own credential without copying
  key files, editing YAML or transferring a certificate fingerprint.
- Existing 0.2.1 computers keep their current enrollment and binding. The one-time
  legacy transition is explicit (`pairing activate-legacy-rebind`) and revokes old
  unpaired authority; it is not activated by installing this release.
- Normal setup/first start prepares the independent updater for the selected role;
  `updates.enabled` defaults to true and an explicit `false` remains an opt-out.
- CLI and Telegram share the same published-artifact check. Ordinary
  `acpgw update --check`, `--stable` and `--version` select the managed service
  automatically and warn before replacing a running installation.
- A Linux Docker dispatcher can use an automatically verified official GHCR image
  pinned by digest; per-version `allow-image` remains only for advanced local images.
- Recovery fixes: an already issued credential survives request expiry until ACK,
  denied pairing requests can be closed locally, and rotating a paired credential
  keeps its binding generation valid.

Upgrade the dispatcher first, then connectors one at a time. Configuration,
enrollment keys, data and existing computer IDs stay in place. SQLite schema 9
adds pairing tables without deleting existing enrollment data.

Automated verification for this source: 1734 passed, 38 skipped; Ruff clean.
Native Windows/Linux service update, a live Docker replacement, Telegram round
trips and reboot/logon persistence remain owner acceptance checks, not claims of
