# ACP Gateway 0.2.6

Fix lost Claude Code answers in Telegram and other channels.

## Fixed

- **Claude Code answers no longer disappear.** Claude Code sends one model message
  as several stream frames (thinking, text, tool call) with the same message id.
  The managed adapter treated the message as finished at the thinking frame and
  dropped all text after it, so intermediate updates and the final answer were
  often lost. Text is now held until each message ends: text before a tool call
  becomes a work update (**🧭 Ход работы**), the rest is the answer, with paragraph
  breaks between messages — the same presentation as Codex. Thinking is never
  forwarded.
- **The Claude Code turn limit no longer breaks the connection.** Reaching
  `max_turns` ended the whole managed agent stream and left the dialogue marked
  busy. The turn now completes with `max_turn_requests` and the task shows a note
  that a follow-up message continues the work (also for `max_tokens`).
- Fewer events per answer reduce the risk of overflowing the adapter's event queue.

## Agent discovery (Telegram «Добавить агента»)

- Candidates and hints name the OS (Windows, Linux, macOS).
- WSL discovery tolerates login-shell banners printed before the probe output.
- On Windows, a Claude Code installed only through npm is reported with a hint to
  run `claude install` (native build) instead of «not found».
- «Not found» hints appear only for agents found nowhere on the PC.

## Upgrade

The Claude Code fix runs on the **connector** (the PC that hosts Claude Code);
update connectors to get it. The turn-limit note is shown by the **dispatcher**.
No configuration or data changes.

Validated with synthetic peers reproducing the real Claude Code frame layout
(confirmed against local Claude Code session transcripts); no model calls.
