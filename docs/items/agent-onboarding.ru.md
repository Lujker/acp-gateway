# P4.18 — добавление агентов на подключённом ПК через диспетчер

**Статус:** PARTIAL — реализовано в `99cc9ba` (версия исходников 0.2.4),
входит в опубликованную 0.2.6; полная живая матрица приёмки не закрыта.
**Репозиторий:** acp-gateway (коннектор, диспетчер, Telegram).
**Текущий выпуск:** диспетчер 0.2.7, коннекторы 0.2.6 по
[журналу развёртывания](../releases/0.2.7-publication.md).
[Инструкция](../setup/telegram-agent-profiles.md).

## Проблема

На 0.2.3 первый агент Codex или Claude Code на подключённом ПК добавляется только
локально: YAML или мастер `acpgw agents configure`, где вручную вводятся
дистрибутив WSL, пользователь, `python`, путь к CLI и `PATH`. Управление профилями
из Telegram ([инструкция](../setup/telegram-agent-profiles.md)) умеет только
копировать уже существующий managed-профиль, поэтому на ПК, где есть лишь Hermes
(work-ПК владельца на 2026-10-26), из бота начать нельзя. Разрешение
`connector.remote_profiles: true` тоже включается правкой конфига и перезапуском.

## Неизменный принцип

`connectors/profiles.py`: «Remote inputs never select executables or accounts».
Диспетчер и бот не передают ПК путь к исполняемому файлу, учётную запись или
команду. Иначе компрометация диспетчера или Telegram даёт выполнение
произвольного кода на всех подключённых ПК. Новая функция сохраняет это:
**ПК сам находит агентов, диспетчер только выбирает из найденного** по
непрозрачному ID кандидата.

## Решения владельца — 2026-10-26

Вопросы заданы после обсуждения предложения, ответы дословно по смыслу:

1. *Разрешать управление профилями при pairing по умолчанию?* — **Да.**
   Осознанный компромисс: новый ПК по умолчанию доверяет аутентифицированному
   диспетчеру менять профили (каталоги проектов, режим safe/work, состав агентов
   из найденных кандидатов). Исполняемые файлы и аккаунты по-прежнему выбирает
   только ПК. Отказ остаётся одним ответом при `acpgw connect` и локальной правкой.
2. *Платформы первой версии?* — **WSL, нативный Windows, Linux и macOS.**
3. *Показывать статус логина CLI?* — **Нет.** Только найденные агенты и
   подключение к ним из Telegram.

## Реализованное решение — 2026-10-26

1. **Обнаружение на коннекторе.** Фиксированные проверки без shell-строк и без
   входных данных от диспетчера:
   - Windows: дистрибутивы WSL2 (`wsl.exe --list`), в каждом — пользователь по
     умолчанию, `python3`, `codex`, `claude` (`command -v` в фиксированном argv);
   - нативные `codex`/`claude` на Windows, Linux и macOS в известных местах
     установки и `PATH` пользователя коннектора;
   - версия CLI (`--version`) как описание кандидата.

   Результат — кандидаты с непрозрачными ID и описанием («Claude Code 2.1,
   Ubuntu-22.04 / user»). Пути и argv остаются на ПК.
2. **«Добавить агента» в Telegram.** Компьютеры → ПК → Добавить агента: список
   кандидатов → каталог проекта (существующий; Linux-путь для WSL) → режим safe/work
   → подтверждение. Коннектор создаёт профиль из своего кандидата, с прежними
   механизмами P4.13: idle-проверка, revision, operation ID, backup конфига.
   После сохранения — initialize-only проверка без промптов и модели.
3. **Разрешение без правки YAML.** Вопрос при `acpgw connect` (по умолчанию «да»);
   для уже подключённых ПК — `acpgw agents allow-remote-profiles`, которая
   включает `remote_profiles` и обновляет установленную службу. Foreground-коннектор
   после команды нужно перезапустить вручную.
4. **Подсказки вместо тупиков.** Ничего не найдено — бот пишет, что установить и
   где (например, `claude` нет в Ubuntu-22.04), без попытки установить самому.

Совместимость: возможность рекламируется коннектором в существующем negotiated
протоколе; старые коннекторы её не объявляют, и кнопка для них не показывается.

## Отклонено или отложено

- **Установка CLI по команде диспетчера** — отклонено: это загрузка и запуск
  кода на ПК по внешней команде, ровно та граница, которую держит проект.
- **Логин CLI через бота** (device code) — отложено: через бота проходят
  чувствительные данные; отдельное обсуждение.
- **Статус логина в карточке кандидата** — не в первой версии (решение 3).

## Критерии готовности

- На ПК только с Hermes владелец добавляет Codex и Claude Code из Telegram
  без локальных правок, для WSL и нативного Windows.
- Нативные Linux и macOS кандидаты обнаруживаются и добавляются; macOS
  проверяется на реальном Mac.
- Диспетчер не может передать путь, argv или аккаунт: проверено тестами
  протокола и отказа на подменённый ID кандидата.
- Новый pairing по умолчанию разрешает управление, отказ работает; команда для
  уже подключённых ПК включает разрешение без ручной правки YAML.
- Старый коннектор 0.2.3 продолжает работать с новым диспетчером.

## Сверка реализации — 2026-10-26

- `connectors/discovery.py` и `_discovery_probe.py`: локальные PATH/известные
  каталоги, WSL2, `--version`, непрозрачные кандидаты со сроком 5 минут;
  `connectors/profiles.py` проверяет ID, revision, каталог и idle, сохраняет backup,
  выполняет initialize без `session/new` и prompt. Неуспешный initialize не удаляет
  сохранённый профиль — бот сообщает о необходимости локальной проверки.
- `channels/telegram_profiles.py`: выбор кандидата, alias вида `codex`/
  `claude_code` с числовым суффиксом при конфликте, каталог, safe/work, подтверждение.
  Предложен домашний каталог, режим по умолчанию safe; форма живёт 2 минуты.
- `cli/wizard.py`: вопрос при настройке подключения; `cli/remote_profiles.py`:
  локальное разрешение через существующую транзакцию обновления службы.
  Старые конфиги не получают разрешение автоматически.
- `481a8f3` (0.2.6): название ОС в кандидатах/подсказках; WSL probe читает последнюю
  непустую JSON-строку после login banner; npm-only Claude на Windows предлагает
  локальный `claude install`. Подсказка «не найден» только для агента, не найденного
  нигде на ПК. CLI не устанавливается и login не проверяется.
- Автотесты: discovery, profiles, remote grant, remote/Telegram profiles; общий
  релизный CI и результаты — [0.2.7 publication](../releases/0.2.7-publication.md).

## Остаток приёмки

Критерии выше сохраняются. Требуются отдельные свидетельства добавления первого
агента на Hermes-only ПК, WSL и native Windows, Linux и реальном Mac, отказа от
разрешения при новом pairing и работы старого коннектора 0.2.3 с новым диспетчером.
Успешный CI macOS не заменяет проверку установленного CLI на Mac.
Список каталогов поиска определён кодом; расширять его при подтверждённом пропуске
реальной установки. Публикации 0.2.4/0.2.5 отдельными записями в репозитории не
подтверждены; номер в коммите реализации не считается доказательством публикации.
