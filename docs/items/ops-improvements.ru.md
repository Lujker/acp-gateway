# P4.19 — эксплуатационные улучшения после 0.2.3

**Статус:** OPEN — набор согласован владельцем 2026-10-26 как следующий пункт после
[P4.18](agent-onboarding.ru.md); порядок подпунктов предложен, не утверждён.
**Репозиторий:** acp-gateway.

Источник — затыки при выпуске и раскатке 0.2.3 2026-10-26
([публикация](../releases/0.2.3-publication.md),
[журнал P4.15.1](updates-out-of-box.ru.md#журнал-2026-10-26)). Каждый подпункт
выпускается отдельно, когда готов; общий срок не задан.

## Подпункты (предложенный порядок)

1. **Надёжный preflight удалённого обновления.** Полная ACL-проверка каталога
   данных — вне пути публикации `connector-activity.json`, чтобы она не могла
   задержать свежесть статуса дольше 5 с. Делается вместе с P4.18 в 0.2.4.
   Затем — первый успешный Telegram round trip коннектора с 0.2.3+.
2. **Видно, куда уйдёт сообщение.** Сейчас обычный текст уходит в активный диалог
   выбранного агента из любого меню, но цель видна только в `/menu` и `/context`.
   Строка «Сообщения уходят: агент@ПК · диалог #N» в каждой панели бота; при
   открытой форме ввода — явное «текст попадёт в форму».
3. **Диагностика ПК из бота.** Кнопка у компьютера: версия, `maintenance` статус
   активности, готовность updater, initialize-only проверка агентов без модели.
   Только фиксированные проверки, без команд от диспетчера.
4. **Понятная причина отказа обновления.** Коннектор знает точную причину
   preflight (активность не подтверждена, занят: N сессий, служба не запущена),
   а бот показывает общее «Проверьте локальное состояние». Передавать
   санитизированный код причины. Плюс подсказка о кэше PyPI сразу после выпуска.
5. **Обновление Docker-диспетчера из бота.** Сейчас `updater not ready: requires …
   Docker host companion`. Устанавливать companion на host при настройке
   Docker-развёртывания; то же доказательство snapshot/rollback, что в P4.15.
6. **Обновление Git-коннектора владельца.** Editable checkout (home-ПК) удалённые
   обновления не поддерживают. Варианты: перевести home на uv registry либо
   научить updater `git pull --ff-only` + перезапуск для явно разрешённого checkout.
   DECISION владельца.
7. **Простаивающие сессии агентов.** 2026-10-26 тестовые codex/claude в WSL жили
   1,5 часа при `running_sessions: 0`. Выяснить, почему коннектор держит процессы
   вне счётчика; автозакрытие после простоя и список открытых сессий ПК в боте.
8. **Релиз одной командой.** Выпуск 0.2.3 занял ~10 ручных шагов (версия, сборка,
   тег, GitHub, PyPI, GHCR, запись публикации). Скрипт с dry-run поверх
   `scripts/build_release.py` и существующего workflow; публикация — только явно.
9. **Нативные Windows-тесты.** 27 стабильных падений и зависание
   `test_connector_control.py` на ПК владельца (воспроизводятся без изменений 0.2.3).
   Таймауты тестов, разбор падений, полный Windows-прогон в CI вместо одного smoke.

## Незакрытые вопросы

- Подпункт 6: перевод home на registry или поддержка Git-обновления.
