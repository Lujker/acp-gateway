### 2026-10-15 — отдельная карточка полного контекста

Добавлен `telegram_context.ContextCard`, `/context`, команда в меню Telegram и
кнопка панели. Главная панель показывает тот же snapshot. Отдельная карточка
включается явно и обновляет одно сообщение. Хранится redacted текст и message ID
в chat-scoped channel state. Данных других чатов нет; текст не содержит сырого
ввода/ответов или зарегистрированных секретов. Для direct backend имя хоста
не придумывается. Для connector различаются регистрация/disabled/offline,
наличие объявления агента и фактическая проверка подключения; RPC не вызывается.

Отдельная task пробуждается после сообщений/callbacks и не реже раза в 5 секунд
проверяет snapshot, включая изменения без Telegram-команды. Последовательный edit
под lock не даёт позднему ответу перезаписать более новый edit; выбор пользователя
никогда не меняется. Контекст и навигационные панели — разные message ID;
ответы, approvals и progress сохраняют свои отдельные сообщения.
Кнопки контекста только навигационные, без изменения маршрута/диалога.

Перед сетевым действием в SQLite записывается unknown. После успешного ACK
сохраняется ready; crash/timeout не создаёт автоматического дубля. Неоднозначный
edit останавливает автообновление и через независимую очередь уведомляет, что
карточка может быть устаревшей. Явный `/context` восстанавливает карточку; при
unknown send возможно существование старой копии. Только подтверждённый
«message to edit not found» разрешает автоматическую замену. Явный 429 даёт backoff.
После restart controls привязываются заново даже при неизменившемся тексте.
Ручное закрепление сообщения оставлено пользователю Telegram.

Первый focused-прогон: **11 passed**. До финальной проверки добавлены отдельность
сообщений, once-only предупреждение при ambiguous edit и восстановление controls.
Первый полный Telegram/Hermes-прогон: **184 passed**. Финальный прогон после усиления restart binding: **184 passed**, 0 skipped,
`dist/telegram-recovery-verification/context-final.xml`. Ruff check/format,
`git diff --check`, secret guard и локальные ссылки изменённых документов прошли.
Полный source suite, native Windows и live Telegram не запускались.
WSL временно отказывал (`Wsl/Service/0x8007274c`) при запуске команд;
проверки возобновлены без перезапуска ПК/WSL/служб, редакторский скрипт записан в dist.
Релизы, push, установки и production обновления не выполнялись.

### 2026-10-15 — продолжение и новый диалог непосредственно у результата

Добавлены прямые кнопки к последнему фрагменту автоматического/ручного результата
и завершённой рабочей карточке. `/open_dialogue JOB_ID` выбирает точный owned
маршрут/диалог без ACP; `/new_from_job JOB_ID` создаёт отдельный диалог того же
агента в исходной папке. Source ownership проверяется при каждом действии;
новый запрос/старая история не воспроизводятся. У удалённого агента этих кнопок
нет, сохранённый результат доступен. Для известного restore-unavailable continuation
не предлагается и явный `/open_dialogue` отказывает до изменения selection.

Новая команда получила chat/message/route/selection и once-only guards.
Найден дополнительный await между consume callback и исполнением — ACK spinner.
После него bound context проверяется повторно, чтобы новый выбор за это время
не был перезаписан. Создание сохраняет защиту ядра от смены target selection;
после RPC отдельно проверяется исходный UI route и selection другого маршрута.
При изменении выбора созданный диалог остаётся записан, но UI не переключается
обратно. Возврат/подтверждение не редактируют исходное сообщение результата.
Outbox content hashes/ACK/unknown fences сохранены: изменяется только markup.

Предварительные result-actions/panel-guards: **37 passed**. Затем добавлены
проверки смены выбора во время callback ACK и запущен общий Telegram/Hermes-набор;
первый общий прогон **201 passed**. Дополнительно проверена смена выбранного
диалога другого маршрута во время RPC: созданный диалог сохраняется, исходный
UI route/selection остаётся прежним. Итог: **202 passed**, 0 skipped;
`dist/telegram-recovery-verification/result-actions-final.xml`.
Ruff check/format, whitespace, secret guard и локальные ссылки изменённых

### 2026-10-15 — недавние диалоги и избранные маршруты

Добавлены `/recent`, `/favorites`, кнопки в главной панели, звёздочки в списке
агентов и `telegram_shortcuts.Shortcuts`. Недавние — 10 metadata-only записей,
отсортированных `last_used_at DESC, id DESC` между агентами только текущего
channel/chat; запрос ограничен в SQLite. В ядре добавлены bounded
`recent_dialogues` и cross-agent `owned_dialogue` с проверкой владельца до
чтения названия/доступности. У удалённых агентов сохранены метаданные и локальные
названия диспетчера без попытки reconnect или подмены маршрута.

Строка списка открывает read-only preview, отдельное действие выбирает точный
owned маршрут/диалог. Кнопка проверяет chat/message/route/selection и once-only,
включая повторную проверку после ACK callback. Известные offline/disabled/
unadvertised маршруты и restore-unavailable диалоги не предлагают продолжение.
Direct backend без подтверждённого соединения помечается «не проверено»,
а не объявляется offline. Никаких ACP RPC при просмотре/выборе не добавлено.

Избранное хранится в channel state по bot/chat: не более 20 маршрутов,
по 10 на странице. Добавление/удаление не меняет выбранный маршрут или активный
диалог. Список имеет revision: старый callback не восстанавливает удалённое
избранное и не отменяет более новую правку. Выбор избранного сохраняет активный
диалог соответствующего маршрута; новый диалог не создаётся автоматически.
Удалённый/offline маршрут остаётся видимым и удаляемым из избранного.
Избранное относится к маршруту, а не к новой сущности проекта/папки.

### 2026-10-15 — завершение кодовой части и подготовка Docker preview

Начальная рабочая карточка теперь показывает «Принято диспетчером» после
успешного submit/создания Job. Затем отдельная status task показывает фактическое
выполнение, approval wait и окончание. Очередь, проценты и неподдержанные вопросы
не выдумываются; отмена и доставка сохранили прежние fences.

Добавлены русские пояснения durable model evidence: intent/pending/unknown/
refused/confirmation_required/observed, deferred и default_required. Принятый
setter не называется применённой моделью без observation. `/model state`
сохраняет полный диагностический JSON и не подключается к агенту. При unknown
кнопка явно вызывает guarded reconcile существующего operation outcome; setter
не повторяется, unknown не очищается по совпавшему имени. Отказ модели и
несовместимый host mode имеют действия; несовместимый host mode не предлагается
лечить автоматическим разрешением действий в gateway `/mode`.

Focused stages/controls/live-session mock tests: **86 passed**. Финальный полный
source suite: **1495 passed / 38 skipped**,
`dist/telegram-recovery-verification/telegram-final-source.xml`.
Пропуски относятся к native Windows/ACL/argv и opt-in installed Hermes.
Ruff check/format, whitespace, secret guard и локальные ссылки проверены.
Native Windows, live Telegram и Docker-сборка/запуск на VPS не выполнялись.

Подготовлен локальный source archive для временного image
`acpgw:telegram-preview-20261015`: только build inputs, исходники и Docker-шаблоны,
без настоящих env/config/state/.git/.venv. Manifest с SHA-256 каждого файла,
отдельный checksum архива и standard-library verifier. Команды Bash проверены
синтаксически; архив проверен по составу и байтам. Dockerfile/Compose сверены с
текущим репозиторием, команды Compose — с официальной документацией через Context7.
[Инструкция](../setup/telegram-preview-docker.ru.md) сохраняет старый image,
