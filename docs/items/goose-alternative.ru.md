# P4.9 — Goose как полноценная альтернатива Hermes

**Статус:** CONDITIONAL — решение 2026-10-23: возвращаться, если Hermes, Codex и Claude Code
через коннектор окажутся недостаточны или появится явная потребность в Goose.
Scope, уточнённый владельцем 2026-10-20, сохранён ниже; расширение не реализовано.
**Репозиторий:** `acp-gateway`.
**Текущий путь:** [Goose endpoint probe](../setup/goose-attach.md).

## Подтверждённая цель

Goose нужен вместо Hermes, если пользователь не может или не хочет использовать
Hermes. Цель — пользовательская равноценность, не одинаковые внутренние протоколы.
Целевая матрица: CLI/Desktop и Windows/WSL/Linux/macOS для обоих агентов. Каждое
сочетание проверяется отдельно: discovery/auth, managed launch/attach, диалоги,
ответы, approvals, model/mode, reconnect, autostart/update. Матрица — направление,
не заявление о проверенной поддержке всех комбинаций.

Обязательны только диалоги, созданные через коннектор/диспетчер. Хранить и подключать
все локальные чаты не требуется. Импорт локально начатой сессии для удалённого
продолжения желателен позже; не блокирует parity и не разрешает shared write/cancel.

## Основа, этапность и границы

Direct Goose ACP, recorded fixtures и explicit endpoint probe уже существуют.
Initialize probe не доказывает Desktop discovery, полный prompt/approval lifecycle
или управление CLI-процессом. Проверить контракт установленных версий без scraping
памяти/логов и скрытого извлечения credentials.

При реализации сначала выбрать одну platform/form combination и пройти весь
пользовательский сценарий, затем расширять матрицу. Первая комбинация и порядок
относительно [VK](vk-bot.ru.md)/P4.10 пока не выбраны. Прежний DEFERRED до P4.8
заменён подтверждённым будущим направлением; в ближайший P4.17/P4.15.1 оно не входит.

Приёмка: new dialogue → prompt/result → allow/deny → model/mode при поддержке →
reconnect, с честным capability status каждого сочетания. Mock evidence не заменяет
live/native. Импорт чатов и управление чужим Desktop-процессом не входят скрыто.
