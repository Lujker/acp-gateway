## Первый приоритет — выполнен как кодовая основа

**Восстановление ответа при сбое Telegram.** `/delivery` теперь различает
завершение задачи и доставку, объясняет неизвестный исход и даёт кнопку
сохранённого результата. Unknown fence сохранён; явный запрос результата
не запускает агент и предупреждает о повторах уже полученных фрагментов.
Живая Telegram-приёмка этой итерации ещё не выполнена.

## Второй приоритет — выполнен как кодовая основа

**Действия для невосстановимого диалога.** При `restore-unavailable` или
`uncertain` с binding `restore=disabled` Telegram предлагает явно создать
новый диалог либо открыть историю задач. Предпросмотр и меню объясняют потерю
подключения и больше не предлагают продолжить недоступный диалог.
Эксплуатационный дефект watcher P3.5 остаётся отдельной задачей общей очереди.

## Третий приоритет — выполнен как кодовая основа

**Переименование кнопками.** Кнопка карточки начинает ввод нового имени
следующим сообщением на пять минут. Кнопка «Отмена», `/cancel` и другая команда
завершают ввод. Название не становится prompt; выбранный диалог не меняется.
Состояние ввода хранится в SQLite и проверяется после повторного открытия.

## Остаток и следующие направления

Кодовая часть четырёх итераций P2.5 завершена. Осталась живая приёмка на двух ПК:
параллельные диалоги, allow/deny/expiry, reconnect, имена, ошибки и независимая
доставка ответа при отказе status edit. Нужна проверка текущей ветки; результаты
автоматических тестов не являются подтверждением установленной версии.
Сверка исходной таблицы из шести направлений и дальнейшая очередь —
[P2.6: контекст и быстрые действия](telegram-context-and-shortcuts.ru.md).

Первый пункт выбран по риску повторного выполнения пользовательской задачи:
при неизвестной доставке нужен доступ к сохранённому ответу, а не повтор prompt.
Приёмка P2.4 ведётся отдельно; автоматические тесты не заменяют живой Telegram.

## Критерии первого пункта

- waiting/pending/sending/delivered/failed/unknown имеют русское объяснение.
- «Отправлена» означает ACK Telegram, не прочтение человеком.
- Завершённый результат доступен кнопкой без ACP и изменения delivery state.
- Для работающей задачи предложено обновление; нет обещания готового результата.
- Refresh и возврат к задаче сохраняют history filter/cursor.
- Чужие chat/message не получают результат; просмотр не раскрывает его текст.

### 2026-10-15 — действия после потери диалога

Сохранены предыдущие незакоммиченные изменения доставки. В Telegram добавлены
проверка фактического availability/binding перед отправкой и карточка с кнопками
«Новый диалог», «История задач», «Диалоги». Отклонённый prompt не сохраняется
для автоматической отправки; пользователь явно создаёт диалог и вводит сообщение.
Статусы неизвестных model operations без `restore=disabled` не объявляются
невосстановимыми. Проверки ядра и протокол восстановления ACP не менялись.

Если binding потерян во время ожидания submit, `SessionNotFound` превращается
в эту карточку только для прежнего route/selection и того же активного диалога.
Если выбор успел измениться, сохраняется обычный отказ без recovery-кнопок,
чтобы поздняя ошибка не предлагала действие для другого маршрута.
Кнопка `/new` использует существующие chat/message/route/selection и once-only
guards. Старый диалог и результаты остаются в истории; скрытого load/prompt нет.

### 2026-10-15 — ввод названия через кнопки

`/rename_hint` теперь начинает ограниченный ввод вместо инструкции набрать
команду. Сохранены текстовая `/rename ID TITLE`, ограничения имени и отдельность
названия диспетчера от Hermes. Ввод привязан к chat, route/selection revision,
ID и created_at диалога; для старого/удалённого/просроченного состояния сообщение
отбрасывается с объяснением, без ACP. Неверное имя позволяет повторить ввод.
Кнопка начала стала once-only и selection-bound; старый cancel nonce не закрывает
более новый ввод. Возврат сохраняет страницу и не выбирает другой диалог.

SQLite state записывается до отправки приглашения: неизвестный исход send
не превращает следующее название в prompt. При отмене другой командой сначала
отправляется уведомление, затем снимается ввод; поздний ответ не отменяет новый
ввод с другим nonce. Сам текст ожидаемого названия не сохраняется в state.
